# EXP BANK v1.12.0

Life Architecture Update · 从 v1.11.0 升级。

本版以四层人生结构组织任务，帮助用户看清基础责任与长期成长。目标是降低每日决策负担；不要求每天完成所有层，也不把任务清空作为成功标准。

> 2026-10-08 简化调整：仍保持 **v1.12.0**，不另起版本号。移除“生活维护每日 15 EXP”与“关键 GROWTH”两套附加规则，让 MAINTENANCE 回归纯人生分类，让 WAR MODE 只承担 CORE 最低运行模式。旧字段保留兼容，但新流程不再依赖。

## 四层结构与使用方式

| 类型 | 含义 | 示例 |
| --- | --- | --- |
| CORE | 核心维持：健康、饮食、睡眠与必须责任 | 吃药、23:00前睡觉、当天课程 |
| GROWTH | 成长推进：学习、技能、项目与职业发展 | 六级单词、Python练习 |
| MAINTENANCE | 系统维护：整理、清洁、财务与设备维护 | 整理文件、汇总OPEX |
| EXPLORATION | 探索体验：兴趣、阅读、社交与旅行 | 看电影、探索咖啡店 |

保留“四象限”入口，内容改为 LIFE ARCHITECTURE。四层分别显示任务数量、名称、EXP、周期、完成状态和统计。点击任务名可编辑；点击“调整顺序”，用上下按钮在该层独立排序，保存后刷新仍保留。完成或撤销会同步刷新状态。

Lists 增加人生分类筛选。新建、编辑、AI HELP 与任务识别预览均支持选择人生分类；自动推荐不准确时可以直接更改。保持原任务集结构，旧 category、core、priority 等字段继续兼容。

## WAR MODE

WAR MODE 的职责收敛为“人生最低运行模式”。

开启后只显示 **CORE**。GROWTH、MAINTENANCE、EXPLORATION 均隐藏，不再提供“关键 GROWTH”星标、复选框或额外判断。真正不可缺少的成长事项，应在特殊时期由用户主动归入 CORE；关闭 WAR MODE 后完整四层任务立即恢复，隐藏不等于删除。

最低目标对每日任务按今天判断，其余按原周期；不限次任务显示但不进入目标分母。以前已完成的单次任务在 WAR MODE 隐藏，正常总览仍保留。完成最低目标后显示“最低目标已达成，可以停在这里”。

旧数据中的 warImportant / core 等历史字段不会被强制删除，以保证旧备份可读；当前 WAR MODE 不再依据 warImportant 决定显示。

## 任务 EXP 简化

四个 Life Architecture 类型现在只负责组织任务，不再叠加“普通积分 / 维护积分”第二套任务结算规则。

- 删除 Lists 中“生活维护 · 今日 X / 15 EXP”进度条。
- 删除“+ 维护任务”快捷入口。
- 新建任务、编辑任务、AI 预览中删除“积分规则”选择器。
- CORE / GROWTH / MAINTENANCE / EXPLORATION 都按任务本身配置的 EXP 正常发放。
- MAINTENANCE 仍可由名称、原分类和任务集自动推断，也可以手动修改，但不会触发每日 15 EXP 封顶。

旧任务如果曾带 taskKind=maintenance，字段仍可被新版本读取和备份，但新的完成行为按任务配置 EXP 正常结算。旧 maintenanceDays 日结数据不主动清空，保留用于旧备份和极短期旧撤销兼容；新完成不再写入它。

## 数据迁移与兼容

任务新增 lifeType、lifeOrder、lifeStatsFrom；状态新增 lifeSchemaVersion=1。lifeType 仅允许四个标准值，lifeOrder 为层内顺序，lifeStatsFrom 是统计开始日期。

缺少 lifeType 时依次结合任务名称、原分类和任务集推断；健康归 CORE、成长学习归 GROWTH、整理维护归 MAINTENANCE、娱乐社交归 EXPLORATION，无法判断归 EXPLORATION。基础课程等必须责任优先归 CORE；推荐可以手动纠正。合法的已有分类始终保留。迁移可重复执行，不清空 localStorage，不要求重新配置。

原 category、EXP、周期、次数、历史、账本和照片保留。移除原先隔日自动清理已完成单次任务的行为，已完成任务保留用于回看。更改人生分类本身不会修改任务周期、记录或积分数值；主动修改周期仍遵循原有周期切换行为。

备份包含新增字段，旧备份可自动迁移。兼容指旧数据可导入新版本；不保证旧代码理解新字段或允许新旧版本同时写入。未知的未来 schema 会阻止覆盖并保留原始备份通道。

## 统计口径

- 今日完成：仅统计每日且周期跨度为 1 的任务，达到当日目标次数后计一项完成。
- 本周完成率：统计本周一至今天、且不早于 lifeStatsFrom 的每日和每周任务。以目标次数为分母，同一周期只计一次，完成次数不超过该周期目标；不计未来日期。
- 新迁移或新建任务从当天开始追踪，避免把未追踪的历史日期当作失败。主动更改周期、跨度或目标次数后重置统计起点。
- 月度、单次和不限次任务显示自身进度，不进入周完成率。没有可统计目标时显示横线。

示例：五项每日任务中三项达标，今日显示 3/5；截至今天应做五次、已做四次，周完成率为 80%。这不是对升级前完整一周的追溯评估。

## AI 任务识别

两个入口共享本地解析与人生分类推荐。明确写出的分类优先；支持逐项预览、修正与设置记忆。冲突或不合法字段需要检查，不会直接自动创建。

“最近睡眠不好，早点睡”可推荐 CORE，“准备六级考试”可推荐 GROWTH；维护类描述可推荐 MAINTENANCE。没有写出的具体时间与积分不会擅自补为 23:00 或 15 EXP。当前仍是本地规则，不具备云端大模型的目标拆解与复杂上下文理解。后续方案见 [AI HELP 的进一步智能化方案](ai-help-next.md)。

## 更新方法与风险

产品版本仍为 **v1.12.0**。为让已安装 PWA 获取这次同版本简化，Service Worker 使用新的内部缓存构建标识，但顶部版本号不变化。通过顶部“↻ 更新”安装即可；无需清除网站数据。

旧版窗口仍打开时会阻止新版本写入；关闭或刷新其他 EXP BANK 窗口后重试。可先通过“备份”导出完整 TXT。

主要剩余风险是关键词推断的语义误分、用户本机时钟变化对周期统计的影响，以及真实 iOS / 厂商浏览器环境差异。分类可手动纠正；旧 maintenance / warImportant 字段仅作兼容保留，不再影响新流程。
