# EXP BANK v1.10.0

2026-10-05 · 基于 main `ade10d05f64a3a46fd415af1b708530530ce366a`（v1.9.2）

记录由目标支付的消费时，OPEX 与 STASH 同时更新。旅游目标可用 1000，记录 200 后剩 800；将消费改为 250 后剩 750；删除这笔纠错记录后恢复 1000。

## 使用变化

- OPEX 的“记一笔”增加付款目标、币种及付款前后余额预览。STASH 卡片的“支出”打开同一窗口并预选目标，实际提交后才记账和扣款。
- 记账与编辑窗口新增“+ 自定义类别”。新类别自动选中，金额、备注和日期保留；空白或同名类别不能重复创建。
- OPEX 顶部增加“类别排序”。吃饭、交通、购物、人情、娱乐、其他和所有自定义类别都能用 ↑ / ↓ 调整，实时保存；新增、编辑和分类统计采用同一顺序。
- 目标卡片突出可用余额，并分别显示当前进度与“曾达成”。“流水 / 取出 / 调整”显示期初、存入、取出、消费和调整，消费可跳回同一 OPEX 编辑器。
- 支出修改金额、付款目标或删除后，同步返还旧目标并按新记录扣款。超额消费、跨币种付款、负数存入和无原因调整会被阻止。
- 目标默认归档，保留余额与历史，可恢复；归档目标不能用于新付款，原关联消费仍可纠错。OPEX 支持按目标和币种筛选。

## 数据与积分

本地键继续使用 `exp-bank-v1`。新增 `moneySchemaVersion: 1`、`defaultCurrencyCode`、`stashMovements` 和有序 `opexCategories`；开销保存 `amountMinor`、`currencyCode`、`categoryId`、`stashId` 与目标名称快照。

目标余额来自资金流水减关联消费；消费只保存在 OPEX，不重复写入另一份消费账。金额使用整数分，兼容的 `amount` / `target` / `saved` 是投影字段。

旧目标以升级前 `saved` 接续期初，不补造历史流水、不重发积分。旧 OPEX 不自动关联目标，不会再扣一次余额；历史币种按升级前全局符号初始化，并提示核对。默认币种切换不会重标旧账或自动换汇。

每日第一笔实际消费记账 +5 EXP，目标首次通过存入达成 +100 EXP。编辑、删除、归档、恢复、取出和迁移不重复奖励。任务与资金奖励同时保存时保留两边 EXP；任务完成或撤销双击防重，保存失败不启动 Bingo 抽奖。

## 保存、备份与更新

- 先持久化，再更新界面和积分；失败时草稿、余额与旧记录保留。移除 800 笔金融历史截断，仅限制展开的显示条数。
- 所有写入通过 Web Locks；不支持时使用 IndexedDB 读写事务互斥。其他页已保存时拒绝旧快照，用户同步后重试，保留未提交草稿。
- 检测不支持新版保存协议的旧窗口，阻止新写入，提示关闭或刷新旧窗口；避免旧版页面覆盖升级后的账本。
- 短码、完整码、TXT 均包含资金与类别顺序。旧备份通过启动时相同的归一化入口完整替换，缺少的资金字段不会混入导入前目标。未知未来 schema 拒绝覆盖，仍可导出原始内容。
- 完整备份保留集锦 Blob；导入恢复数字图片 ID。照片恢复失败单独说明，不先清空已有图片库；照片缺失时不伪报完整备份成功。
- React / ReactDOM 18.3.1 随包提供，字节与原运行时 SRI 一致。`support.js`、`image-slot.js`、manifest 和图标保持原仓库内容。
- SW 先下载并验证完整资源，再准备切换。HTML / JS 使用同一版缓存；缺 JS 不回退成 HTML，404 不写入正式缓存。更新只清理本应用旧缓存，保留本地账本、照片及其他应用缓存。

## 版本边界

本版完成原升级方案的 P0 / P1，并补齐自定义类别与所有类别排序。奖励 Green / Amber / Red 分级、摩擦系数、Maintenance EXP 和 LIVE 等后续需求未在本版改动。

首次使用升级版前，可从现有“备份”导出完整 TXT；更新时保留本机数据。产生新版交易后，优先前向修复，避免把旧前端与新资金 schema 混用。代码版本包不包含日常用户账本，也不能代替个人数据备份。
